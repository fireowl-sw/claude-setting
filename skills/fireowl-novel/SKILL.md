# Fireowl Note - Canvas 小说创作系统

## 概述

使用 Obsidian Canvas 作为可视化编辑界面，实现 AI 辅助中文网络小说创作。从现有章节提取故事结构，在 Canvas 中修改，生成新章节的同时保持与总纲一致并学习用户偏好。

## 项目结构

```
小说项目/
├── 00_总纲.canvas              # 总纲（世界观、人物、剧情）
├── 01_输入素材/                # 原始章节输入
├── 02_思维导图/                # Canvas 思维导图
├── 03_我的作品/                # 生成的章节
└── 04_风格学习库/              # 风格学习数据库
```

## 核心工作流

### 步骤 1：提取章节结构到 Canvas

**输入**：来自 `01_输入素材/` 的原始章节 markdown 文件

**处理流程**：
1. 读取源章节
2. 识别核心冲突（中心节点，红色）
3. 提取场景（蓝色节点）
4. 细化人物动作、对话、情绪（嵌套节点）
5. 创建因果关系连线

**⚠️ Canvas 创建规范**：
- **必须使用 `json-canvas` skill** 创建 Canvas 文件，确保格式正确
- **或者严格遵循 JSON Canvas Spec 1.0**：
  - 所有 `id` 必须是 **16 字符十六进制字符串**（如 `"a1b2c3d4e5f67890"`）
  - 禁止使用语义化 ID（如 `"scene1"`, `"core-conflict"`）
  - 参考 `json-canvas` skill 获取完整格式规范

**输出**：`02_思维导图/框架_{书名}_第N章.canvas`

**Canvas 节点结构**：
```
[核心冲突] (红色，居中)
  ├─ [场景1] (蓝色)
  │   ├─ 人物动作 (紫色)
  │   ├─ 对话意图 (黄色)
  │   └─ 情绪变化 (绿色)
  ├─ [场景2] (蓝色)
  └─ [场景3] (蓝色)
```

**颜色编码**：
- 🔴 红色 (`color: "1"`) - 核心冲突
- 🔵 蓝色 - 场景
- 🟣 紫色 - 动作
- 🟡 黄色 - 对话
- 🟢 绿色 (`color: "4"`) - 情绪
- 🟠 橙色 (`color: "2"`) - 冲突升级
- ⚫ 灰色 - 伏笔

### 步骤 2：用户在 Canvas 中修改

用户在 Obsidian 中打开 Canvas 并：
- 添加/删除/移动节点
- 修改节点内容
- 调整连接线
- 改变场景顺序

**输出**：修改后的 Canvas（覆盖或另存为新版本）

### 步骤 3：生成新章节

**输入**：
- 来自 `02_思维导图/` 的修改后 Canvas
- 来自 `01_输入素材/` 的原始章节
- 来自 `00_总纲.canvas` 的总纲

**连贯性检查**（自动执行）：
1. ✅ 人物性格符合总纲设定
2. ✅ 剧情与前面章节衔接
3. ✅ 时间线连贯
4. ✅ 世界观规则一致

**风格模仿**：
- 句式长短和结构
- 词汇难度
- 修辞手法（比喻、排比）
- 叙事视角和节奏
- 感官细节

**输出**：`03_我的作品/{书名}_第N章.md`

**警告示例**：
```
⚠️ 连贯性检查发现问题：
- 第 9 章提到主角受伤，但第 10 章框架显示在战斗
- 总纲设定主角"冷静"，但框架显示过于情绪化

建议修复：
1. 在 Canvas 中添加"伤势限制行动"节点
2. 调整情绪为"表面冷静，内心波动"

是否应用建议？[是/否]
```

### 步骤 4：学习用户模式（自动执行）

**分析和记录**：
- 原始章节的风格特征
- 用户的 Canvas 修改习惯
- 生成质量反馈

**保存到**：`04_风格学习库/风格档案_{作者}/`

**学习内容**：
```markdown
# 风格档案：{作者}

## 语言特征
- 句式长短：[短/中/长]
- 词汇难度：[通俗/典雅/专业]
- 修辞手法：[比喻/排比/反问]

## 叙事特征
- 视角：[第一人称/第三人称限制/全知视角]
- 节奏：[快/慢/变化]
- 描写偏好：[心理/动作/环境]

## 用户修改习惯
- 倾向于：[增加冲突/压缩节奏/更换场景]
- 常用场景：[雨夜/咖啡馆/天台]
- 节奏偏好：[快节奏推进/慢节奏铺垫]
```

## Canvas 创建规范

### ⚠️ ID 格式要求

**正确的 ID 格式**（16 字符十六进制）：
```json
{
  "id": "a1b2c3d4e5f67890",
  "id": "b2c3d4e5f6789012",
  "id": "f67890123456789a"
}
```

**❌ 错误的 ID 格式**（会导致文件无法打开）：
```json
{
  "id": "scene1",           // 语义化 ID
  "id": "core-conflict",    // 带连字符的 ID
  "id": "scene-1",          // 带连字符的 ID
  "id": "e1"                // 过短的 ID
}
```

### Python ID 生成示例

```python
import random

def generate_canvas_id():
    """生成符合 JSON Canvas 规范的 16 字符十六进制 ID"""
    return ''.join(random.choices('0123456789abcdef', k=16))

# 使用示例
node_id = generate_canvas_id()  # 如 "a1b2c3d4e5f67890"
```

## Canvas 读取指南

### 节点类型

**文本节点**：包含 markdown 内容
```json
{
  "type": "text",
  "text": "# 场景标题\n\n关键情节..."
}
```

**文件节点**：引用外部文件
```json
{
  "type": "file",
  "file": "path/to/file.md",
  "subpath": "#heading"
}
```

**分组节点**：可视化容器
```json
{
  "type": "group",
  "label": "章节分组"
}
```

### 连接关系

读取连接线以理解剧情流向：
```json
{
  "fromNode": "scene1",
  "toNode": "scene2",
  "label": "触发"
}
```

**常用连接标签**：
- "导致" (leads to)
- "触发" (triggers)
- "解决" (resolves)
- "伏笔" (foreshadows)

### 布局解读

- X 向右增加，Y 向下增加
- 节点可以有负坐标
- 使用节点位置理解场景顺序
- 分组节点组织相关场景

## 总纲 (00_总纲.canvas)

**生成前必须读取**以检查连贯性。

**关键部分**：
1. 🌍 **世界观** - 时代、力量体系、势力
2. 👥 **人物** - 主角、伙伴、反派
3. 📚 **主线剧情** - 分卷大纲、时间线
4. 🎨 **风格** - 参考作品、视角、节奏
5. ⚠️ **约束** - 人物/世界不能做的事

**更新进度**：在时间线中标记已完成的卷/章

3. 应用用户修改偏好
4. 结合 Canvas 结构

## 重要提示

1. **生成前必须检查 `00_总纲.canvas`** 以确保连贯性
2. **⚠️ Canvas 文件格式**：
   - **必须使用 `json-canvas` skill 创建 Canvas 文件**
   - 所有节点和边的 `id` 必须是 **16 字符十六进制字符串**
   - 使用语义化 ID（如 `"scene1"`）会导致文件无法在 Obsidian 中打开
3. **读取时保留 Canvas 结构** - 节点和连线承载剧情信息
4. **从每次生成中学习** - 自动更新风格库
5. **生成前警告用户**连贯性问题
6. **在 Canvas 创建时一致使用颜色编码**
7. **尊重用户修改** - Canvas 是用户的创作空间
